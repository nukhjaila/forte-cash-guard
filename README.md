# ForteBank Cash Guard AI — Datathon 26

Локальный AI-сервис для автоматизированного выявления визуальных признаков нарушений кассовой дисциплины по видеозаписям с камер наблюдения.

Решение предназначено для локального запуска без обращения к внешним облачным AI-сервисам. Сервис не использует биометрию или распознавание лиц и может быть перенесён во внутренний контур банка.

## 2. Архитектура и история разработки

### Эволюция подхода

**Первый этап — локальная VLM.** На начальном этапе тестировался мультимодальный пайплайн на основе Qwen2.5-VL-3B через Ollama. Кадры объединялись в сториборды. По результатам экспериментов компактная VLM при ограниченном объёме VRAM могла генерировать ложные срабатывания, зацикливать генерацию и неточно определять таймкоды.

**Текущий подход — RF-DETR Small + Temporal Rules Engine.** Для повышения воспроизводимости и скорости обработки используется двухэтапный пайплайн компьютерного зрения:

1. Видео разделяется на обучающую и отложенную (`holdout`) выборки с помощью `step1_setup.py`, чтобы избежать утечки тестовых данных.
2. С помощью Zero-Shot-модели Grounding DINO (`autolabel.py`) создаётся предварительная разметка ключевых кадров для 15 целевых классов.
3. Предварительная разметка фильтруется с помощью `filter_coco.py`.
4. В CVAT вручную проверяются и уточняются bounding boxes. Дополнительная разметка выполняется в две итерации с помощью `train_assist.py`.
5. На проверенном датасете дообучается детектор RF-DETR Small. Веса модели располагаются по пути `models/assist/checkpoint_best_total.pth`.
6. Результаты детекции обрабатываются детерминированным временным движком правил `backend/app/ai_engine/rules_engine.py`.
7. События сопоставляются с базой нормативных актов `backend/app/knowledge_base/rules_kz.json`.

### Схема обработки видео

```text
Видеофайл .mov
      |
      v
FastAPI + Async Queue Worker
(последовательная обработка для снижения нагрузки на GPU VRAM)
      |
      v
1. Декодирование и выборка кадров (OpenCV, 5 FPS)
      |
      v
2. Детекция 15 классов объектов
   RF-DETR Small, confidence threshold = 0.35
      |
      v
3. Вычисление пространственно-временных признаков:
   - присутствие кассира в рабочей зоне относительно ноутбука
     или счётчика банкнот;
   - состояние сейфа и двери;
   - расположение наличных денег, инкассаторских сумок,
     ключей и посторонних предметов.
      |
      v
4. Temporal Rules Engine
   (порог длительности min_dur и сглаживание разрывов MAX_GAP)
      |
      v
5. Выбор 1–3 кадров-доказательств с bounding boxes
   (JPEG Base64) и сопоставление с нормативными актами РК
```

### Используемые модели и библиотеки

- **RF-DETR Small (`rfdetr`)** — локальная модель детекции объектов.
- **OpenCV** — декодирование видео и обработка кадров.
- **FastAPI** — веб-сервис и API.
- **Pydantic** — валидация данных.

После загрузки весов модель выполняет инференс локально. Согласно текущей архитектуре, внешние облачные AI API при инференсе не используются. Перед коммерческим использованием проверьте лицензии конкретных версий всех зависимостей.

### Классы детектора

Модель предназначена для обнаружения 15 классов:

`person`, `money`, `safe_open`, `safe_closed`, `key`, `id_card`, `laptop`, `bag`, `cup`, `personal_item`, `journal`, `stamp`, `door_open`, `door_closed`, `money_counter_machine`.

## 3. Нормативная база Республики Казахстан

События сопоставляются с нормативными правовыми актами Республики Казахстан. В проекте используется база правил `backend/app/knowledge_base/rules_kz.json`.

### Постановление Правления Национального Банка Республики Казахстан от 29 ноября 2019 года № 231

Документ регулирует кассовые операции и операции по инкассации банкнот, монет и ценностей в банках второго уровня, филиалах банков-резидентов Республики Казахстан, Национальном операторе почты и соответствующих юридических лицах.

В описании проекта выделены следующие положения:

- **Глава 2:** организация кассовой работы и хранение наличных денег и ценностей; требования к дверям кассовых помещений, доступу посторонних лиц, хранению денег и ценностей в запираемых сейфах, ключам и посторонним предметам на рабочем столе.
- **Главы 3, 4 и 6:** приём и выдача наличных денег, а также пересчёт банкнот.
- **Глава 5:** приём и обработка инкассаторских сумок; контроль за тем, чтобы сумки с наличными деньгами и ценностями не оставались без присмотра.

### Постановление № 48 о требованиях к информационной безопасности

В проекте также учитываются требования к информационной безопасности банков и организаций, осуществляющих отдельные виды банковских операций. В частности, в описании решения отмечены блокировка автоматизированного рабочего места при временном отсутствии сотрудника и контроль оборудования по завершении смены.

> Перед использованием результатов для принятия официальных решений необходимо проверить актуальную редакцию нормативных актов и точное соответствие каждого правила применимому пункту документа на официальном правовом портале «Әділет»: https://adilet.zan.kz/.

## 4. Распознаваемые типы нарушений

Движок правил находится в `backend/app/ai_engine/rules_engine.py`. Ниже приведены типы событий и минимальная длительность, указанная в конфигурации проекта.

| Код правила | Категория | Условие срабатывания | Минимальная длительность |
|---|---|---|---:|
| `door_open_start` | `DOOR_AND_ACCESS_CONTROL` | Дверь кассового помещения обнаружена открытой в начале или в ходе работы | 2 с |
| `too_many_people` | `DOOR_AND_ACCESS_CONTROL` | В помещении одновременно обнаружены 3 или более человек | 3 с |
| `safe_open_long` | `SAFE_AND_STORAGE_RULES` | Сейф остаётся открытым дольше заданного порога | 6 с |
| `key_left` | `SAFE_AND_STORAGE_RULES` | Ключ обнаружен в замочной скважине, на сейфе или рядом с ним | 4 с |
| `money_unattended` | `SAFE_AND_STORAGE_RULES` | Наличные обнаружены вне сейфа, а кассир не определяется на рабочем месте | 3 с |
| `bag_unattended` | `INCASSATION_BAG_UNATTENDED` | Инкассаторская сумка находится в помещении без присмотра кассового работника | 3 с |
| `drink_on_desk` | `PERSONAL_ITEMS_AND_FOOD` | На рабочем столе в зоне работы с наличностью обнаружен стакан с напитком | 2 с |
| `personal_items_on_desk` | `PERSONAL_ITEMS_AND_FOOD` | На рабочем столе обнаружены посторонние личные предметы | 3 с |

### Устойчивость к изменению ракурса камеры

Присутствие кассира определяется относительно динамически обнаруживаемого положения ноутбука (`laptop`) или счётчика банкнот (`money_counter_machine`), а не только по фиксированным координатам пикселей. Такой подход может повысить устойчивость правил при изменении ракурса, но фактическая точность зависит от качества видео и детекции объектов.

## 5. Ограничения решения и известные ошибки

### Процедурные действия без выраженного визуального признака

Детектор объектов не может надёжно устанавливать действия, которые требуют распознавания мелкой моторики, чтения содержимого экрана или проверки банковских данных. К таким случаям относятся:

- факт проверки или непроверки удостоверения личности клиента либо инкассатора;
- выдача клиенту неполной суммы после пересчёта или смешивание купюр разных клиентов;
- факт программной блокировки экрана ноутбука, если состояние экрана неразличимо на видео;
- отключение небольших переключателей и других малозаметных элементов оборудования.

### Маленькие и редко встречающиеся объекты

Классы `key`, `stamp`, `id_card` и `personal_item` могут занимать небольшую часть кадра и иметь ограниченное количество примеров в обучающей выборке. При плохом освещении или перекрытии объекта руками возможны пропуски обнаружения (false negatives).

### Ложные срабатывания и проверка человеком

В описании проекта заявлена настройка на высокий Recall и значение `Recall = 1.00` на отложенной выборке `holdout`. Этот результат относится к конкретной выборке и не гарантирует такой же показатель на новых видео. В пограничных ситуациях, например при временном уходе кассира в начале или конце ролика, возможны срабатывания, которые должен проверить специалист.

### Данные, недоступные для анализа по видео

Сервис анализирует видеопоток и не проверяет:

- корректность кассовых проводок в АБИС;
- номиналы купюр, если они не определяются доступными средствами;
- подлинность банкнот по водяным знакам и другим защитным признакам.

Результаты системы следует рассматривать как подсказку для специалиста, а не как окончательное подтверждение нарушения.

## 6. Установка и запуск

### Требования

- **ОС:** Linux (Ubuntu/Debian), WSL2 или Windows 10/11.
- **Python:** 3.10 или новее.
- **Вычислительные ресурсы:** GPU с поддержкой CUDA и ориентировочно от 6 ГБ VRAM либо CPU. В исходном описании проекта указано тестирование на NVIDIA RTX 4050 Laptop.
- **Веса модели:** `models/assist/checkpoint_best_total.pth`.

### Шаг 1. Клонирование репозитория и установка зависимостей

```bash
git clone https://github.com/nukhjaila/forte-cash-guard.git
cd forte-cash-guard

pip install -r backend/requirements.txt
pip install rfdetr torch torchvision pillow
```

### Шаг 2. Размещение весов модели

Убедитесь, что файл обученной модели находится по следующему пути:

```text
models/assist/checkpoint_best_total.pth
```

### Шаг 3. Настройка API-ключа и запуск сервера

**Linux / macOS / WSL2:**

```bash
export X_API_KEY="replace-with-your-secret-key"
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

**Windows PowerShell:**

```powershell
$env:X_API_KEY = "replace-with-your-secret-key"
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

Используйте один и тот же секретный ключ в переменной окружения сервера и при обращении к API. Не храните настоящий ключ в репозитории.

### Шаг 4. Использование веб-интерфейса

1. Откройте `http://localhost:8000` в браузере.
2. Введите настроенный API-ключ, если интерфейс его запрашивает.
3. Выберите видеофайл `.mov` и нажмите **«Проверить видео»**.
4. Дождитесь завершения обработки.
5. Изучите итоговый результат, найденные события, таймкоды, ссылки на нормативную базу и кадры-доказательства с разметкой объектов.

Набор поддерживаемых форматов и фактическое поведение интерфейса зависят от реализации текущей версии приложения.

## 7. Оценка на holdout-выборке

Для запуска оценки на отложенной выборке выполните:

```bash
python eval/run_eval.py --split holdout
```

Используйте отложенную выборку для оценки качества модели на данных, которые не использовались при обучении. Результаты тестирования следует интерпретировать с учётом размера и состава выборки.
